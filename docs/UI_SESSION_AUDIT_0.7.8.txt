TotalWarcraft 0.7.8 - UI and session journal audit
November 22, 2026

REPORTED INCIDENT

after incoming opposing-player damage was confirmed for meter session 16.
The reporter saw their own toast, then clicked it while still fighting.
WoW displayed "Interface action failed because of an AddOn".
That export contains no blocked-function or click event. It does NOT establish

CHANGES
- Accepted local submissions carry local-only provenance after validation.
  Self echoes also compare the normalized full player identity. Neither can
  produce a toast or consume the next peer-alert cooldown.
- A clicked report waits for PLAYER_REGEN_ENABLED before opening details.
  The next-frame callback checks lockdown again. Expired/deleted reports, zone
  transitions and another open TotalWarcraft window cancel the deferred view.
  Right-click dismisses only. Map pins and stored own reports remain available.
- Our close buttons call Hide on their own custom frame. They do not invoke the
  Blizzard UIPanel manager. This is an additional combat safeguard, not proof
  that the user's original LEFT-click failure came from the close button.
- An old IsInGuild condition remained in AutoReports despite the 0.7.7 shared
  transport. It has been removed. Unguilded users now take the same automatic
  incoming-damage verification/send path.

SESSION JOURNAL V2
Relevant lifecycle, combat/target state, verification starts/reads/outcomes,
observed enemy identities, one matched damage row, report sends/receipts and
duplicates, channel state, commands (verb only), window/button/map actions,
UI errors and native blocked/forbidden actions are recorded.
Existing Finder, invitation, warband, scouting and transfer traces remain.
Named-addon/function fields are native attribution, not proof of original taint.

Readable Lua messages/stacks delivered to ScriptErrorsFrame are observed using
a secure post-hook. TotalWarcraft button errors are logged and rethrown.
No replacement of geterrorhandler/seterrorhandler, no changes to scriptErrors
CVars, no error suppression and no inspection of error locals. If another error
handler intercepts an error before Blizzard receives it, this observer cannot
promise that error will appear. Export states whether the observer attached.

Loaded-addon versions (up to 256), game build, ruleset and faction remain in the
export header even after old activity is evicted. Names/locations/error text can
appear. No chat-event subscription, packet contents or automatic upload.

This is a bounded operational journal, not every WoW event or every damage hit:
1500 activity entries (600-character messages), 64 separately reserved issue
entries (1600-character messages), finite burst/rate budgets and omission counts.
Routine floods cannot consume the issue budget. Logging adds no polling timer.
Export before reload/logout; the journal intentionally resets at the next UI
session. No dummy data, diagnostic command or development tool was added to
the release build.

OFFLINE VALIDATION
All 20 tests/test_*.py suites passed, including source and compiled Release.
New shared scenarios cover:
- own reports, normalized self echoes, cross-route deduplication, peer toasts;
- no frame creation/native panel actions on a combat toast click;
- post-combat opening, expiry/removal/zone/window cancellation, right-click;
- direct custom close in combat, no repeated deferred request on refresh;
- untrusted local-provenance input rejection;
- preserving normal error-handler processing and callback return values;
- blocked/forbidden capture, secret redaction, no locals, inventory, budgets;
- automatic unguilded damage report over CHANNEL.
Existing OpenMap transforms, Finder ownership/consent, UI navigation, report
validation, release stripping and no-idle-timer regressions also pass.
Offline mocks cannot reproduce the game's taint engine or prove addon coexistence.
