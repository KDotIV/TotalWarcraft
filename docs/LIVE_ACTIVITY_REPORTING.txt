BEHAVIOR
- Start one five-second timer when an eligible fresh capture begins.
- Check while still in combat, repeating every five seconds until submission,
  combat end, invalidation or the existing fifteen-minute capture limit.
- Require a fresh correlated native session, readable local source identity,
  positive new per-unit damage, and an unambiguous observed opposing player.
- DamageTaken and DamageDone are independent; either direction can qualify.
  Both use combatSpellDetails.amount and reject mob/pet unit details. TotalAmount
  is never accepted in place of missing per-unit attribution.
- Compare each tick with prior readable amounts, retaining high-water marks.
  An unreadable/missing sample requires re-priming before later growth qualifies.
  Unseen player names are included in baselines so later targeting cannot replay
  old damage. Rows, identities, sessions and capture lifetime remain bounded.
- Submit at the current position while still in the captured map. Preserve one
  attempt per combat, shared two-minute cooldown and existing channel transport.
- Cancel at combat end, disable/reload, zone/transfer/reset, or invalid context.
  Short fights do not produce delayed reports. No idle timer is left running.
- Journal records interval=5, phase=combat checks, accepted direction/opponent,
  and missing session / restricted attribution / no recent evidence separately.

NATIVE LIMITATION
Blizzard marks GetCombatSessionFromID and GetCombatSessionSourceFromID as
SecretWhenInCombat. Protected fields remain unusable. The new timer does not
bypass this: calls are guarded and every field is checked before use. If live
damage attribution is unavailable, it skips instead of substituting UNIT_COMBAT,
health changes, target selection or combat flags, which cannot exclude unrelated
NPC damage. Five-second reports on the current live client are NOT established.
The prior live DamageDone samples also lacked victim attribution. This change
accepts that direction only if readable per-unit evidence actually exists.
